# Джун

Домашний журнал для приготовления комбучи джун, где за основу вместо черного чая и сахара берутся зелёный чай и мёд.

«Джун» ведёт вас за руку через весь цикл — от заваривания чая с мёдом до дегустации готового напитка. Он помнит параметры каждой партии, подсказывает, когда проверять pH, следит за карбонизацией через контрольную ПЭТ-бутылку и хранит историю каждой бутылки.

---

## Что умеет

- **Медочай** — учёт заваривания: сорт чая, температура, время настаивания, сорт и количество мёда, стартовая плотность (°Brix). Черновики: можно сохранить недозаполненный рецепт.
- **База (лимонадница)** — первичное брожение (F1) с напоминаниями о проверке pH, фиксация финального pH и плотности, автоматический расчёт ABV.
- **Бутылки** — розлив с добавками или без, вторичное брожение (F2), контрольная ПЭТ-бутылка, охлаждение, хранение, дегустация, утилизация с указанием причины.
- **История** — каждое действие по медочаю, базе и бутылке логируется. Можно редактировать и удалять отдельные записи.
- **Блокнот** — свободные заметки, не привязанные ни к какой партии. Рецепты «на будущее», наблюдения, расчёты.
- **Калькулятор объёма** — считает объём лимонадницы по диаметру и высоте (с поправкой на бортик).
- **Бэкапы** — JSON-дампы всех таблиц с ротацией (3 последних). Импорт/экспорт через UI.

## Как это работает

### Стадии

```
Медочай → F1 (база) → Розлив → F2 (бутылки) → Холодильник → Хранение → Выпито
                                  ↘ F3 (бутылки с добавками)
```

**F1 — первичное брожение.** Медочай + стартер от предыдущей партии заливаются в лимонадницу. Цель — pH ~3.5 (обычно 3 дня). По достижении — розлив.

При розливе в лимонаднице **сознательно оставляется 150–200 мл сусла** — это стартер для следующего цикла. Он остаётся под тканью при комнатной температуре и идёт в долив следующей партии. Если цикл не планируется — стартер можно слить в банку, закрыть и убрать в холодильник на 1–2 недели.

**F2 — вторичное брожение.** Бутылки карбонизируются. Одна бутылка в партии — **контрольная ПЭТ**: по её надуванию судят о готовности. Если ПЭТ нет, ориентируются на 3 дня с конца F1 (или форсируют вручную).

**F3 — третья стадия.** Только для бутылок с добавками (соки, специи, сахар для карбонизации). Пока в разработке. Справочный алгоритм F3 — в `ALGORYTHM.md` §6.

**Холодильник.** Минимум 12 часов — останавливает брожение, осаждает дрожжи.

**Хранение.** Готово к употреблению.

### Контрольная ПЭТ-бутылка

В каждой партии одна бутылка **может быть** помечена как ПЭТ — контрольная. По ней судят о карбонизации всей партии: если ПЭТ надулась — пора в холодильник. ПЭТ нельзя удалить, пока в партии есть другие бутылки, — иначе партия останется без контроля.

### Расчёт алкоголя

ABV считается по формуле через Brix → SG (specific gravity):

```
SG = Brix / (258.6 − Brix / 258.2 · 227.1) + 1
ABV = 76.08 · (OG − FG) / (1.775 − OG) · (FG / 0.794)
```

где OG — стартовая плотность (из медочая), FG — финальная (при завершении F1). Если FG ≥ OG — ABV = 0.

### Правила мёда

- Мёд для старта — **только светлый и монофлорный**.
- Тёмный мёд — только на стабильной (3+ месяцев) культуре и всегда с разбавлением **50/50** светлым мёдом.

### Правила культуры

- Новую плёнку на старте **ни в коем случае нельзя разрушать**.
- Стартовый гриб может подняться и прирасти к новой плёнке. Если лежит на дне — пускай лежит.
- Выбрасывать культуру стоит, если появился **чёрный налёт**.

## Технологии

- **Backend:** Python 3.10+, FastAPI, SQLite (без ORM — чистый SQL), Pydantic.
- **Frontend:** ванильный JavaScript, один HTML-файл, CSS. Без фреймворков и сборки.
- **Хранилище:** SQLite-файл `dzhun.db` рядом с кодом.
- **Бэкапы:** JSON-дампы в `backups/`.

## Установка и запуск

### Требования

- Python 3.10+
- pip

### Установка

```bash
git clone <repo-url> dzhun
cd dzhun
pip install fastapi uvicorn python-multipart
```

`python-multipart` нужен для загрузки файлов при восстановлении из бэкапа.

### Запуск

```bash
python main.py
```

Приложение поднимется на `http://0.0.0.0:8000`. Откройте в браузере — интерфейс адаптирован под мобильные устройства, удобно пользоваться с телефона в домашней сети.

### Структура

```
dzhun/
├── main.py              # весь backend
├── dzhun.db             # SQLite (создаётся автоматически)
├── backups/             # JSON-бэкапы (создаётся автоматически)
├── static/
│   ├── app.js           # весь frontend
│   ├── style.css        # стили
│   └── favicon.png      # иконка
└── templates/
    └── index.html       # HTML-шаблон
```

## Бэкапы

- **Создать бэкап** — кнопка «Бэкап» в шапке или `POST /api/backup`.
- **Скачать последний** — `GET /api/export`.
- **Восстановить** — кнопка «Импорт» в шапке, выбрать JSON-файл.
- **Ротация** — хранятся только 3 последних бэкапа.

При восстановлении **все текущие данные перезаписываются**. Поля, которых нет в текущей схеме (например, от старых версий), отбрасываются — старые бэкапы совместимы.

Рекомендую делать бэкап перед каждым крупным действием: розливом, импортом, экспериментами.

## Ограничения и особенности

- **Без аутентификации.** Приложение рассчитано на локальный запуск или домашнюю сеть. Не выставляйте его в открытый интернет.
- **Один пользователь.** Нет разделения доступа, нет многопользовательского режима.
- **Нет миграций.** Схема создаётся через `CREATE TABLE IF NOT EXISTS`. При изменении схемы нужно либо накатывать `ALTER` вручную, либо удалять `dzhun.db` (потеряв данные). Бэкап перед обновлением — обязателен.
- **Один медочай — одна база.** Если медочай использован для базы, его нельзя редактировать или удалить. Для повторного использования рецепта — создайте новый медочай.
- **F3 в разработке.** Бутылки с добавками переходят в стадию `f3`, но действий для них пока нет.
- **`bottles.abv` — денормализация.** Копия `jar.abv`, будет пересчитываться, когда появится F3 (добавки меняют ABV).

## Философия проекта

«Джун» — это **софт для себя**. Он не пытается быть универсальным, не поддерживает другие процессы брожения, не имеет плагинов и API для интеграций. Он решает одну конкретную задачу: вести домашний журнал медовухи на чайной закваске так, чтобы ничего не забыть и не запутаться.

Отсюда — минимализм: один файл backend, один файл frontend, SQLite, никаких зависимостей кроме FastAPI и Pydantic. Проект легко поднять на Raspberry Pi, на домашнем сервере или просто на ноутбуке.
